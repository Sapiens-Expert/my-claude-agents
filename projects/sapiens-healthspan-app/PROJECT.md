# SapiensOS HealthSpan app

- Status: Pre-build/validation
- Thesis: convert fragmented health signals into prioritized behavior execution.
- Gate: demonstrated demand and safe prototype behavior before substantial build or raise.

The expanded brand pyramid mentions wearables, assessment, privacy-first EU design, and an iOS application as functional benefits. These are intended product attributes, not current implemented capabilities or compliance evidence.

See [product positioning](../../brands/sapiens-os/positioning.md) and [active decision](../../decisions/active/2026-07-11-delay-healthspan-app.md).

## Validation sequence

Apply the [product validation loop](../../frameworks/consulting/product-validation-loop.md):

1. Validate one narrow execution problem with coaching/manual delivery evidence.
2. Test a low-fidelity prototype on a real task without collecting unnecessary health data.
3. Seek behavior-bearing commitments: repeated use, paid pilot/deposit, or organizational pilot commitment.
4. Measure value realization, non-use, support burden, safety/privacy concerns, and retention—not only interest.
5. Revisit build/fundraising only when the active decision's gate is met.

Membership, subscription, community, wearable integration, broad personalization, and multiple tiers remain model hypotheses. They do not become roadmap commitments because the source library contains playbooks for them.
